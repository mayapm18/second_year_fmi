## **1. Error Components**
Each error in SQL Server has:
- **Error Number** - Unique identifier
- **Error Message** - Descriptive text
- **Severity** - 1-25 (higher = more serious)
- **State** - Internal engine state code
- **Procedure** - Name where error occurred
- **Line Number** - Where error happened

## **2. Custom Error Messages**
- **Create with `sp_addmessage`**: `sp_addmessage 50001, 10, 'Unexpected value'`
- **Must be >= 50001** (system errors are < 50001)
- **WITH LOG option**: Logs to Windows Application log/SQL error log
- **Used for alerts** - Alerts only fire on logged errors

## **3. RAISERROR vs THROW**

| **Feature** | **RAISERROR** | **THROW** |
|-------------|---------------|-----------|
| **Error Numbers** | Can use existing or 50000 | Must be >= 50000 |
| **Severity** | 0-25 (user-defined) | Always 16 |
| **Message Source** | From sys.messages or inline | Inline only |
| **Requires ;** | No | Yes (statement terminator) |
| **Formatting** | Supports `%s`, `%d` placeholders | No placeholders |
| **Transaction State** | No automatic rollback | With XACT_ABORT ON: aborts transaction |

**RAISERROR example:**
```sql
RAISERROR('Custom error: %s %d', 10, 1, 'Message', 2);
```

**THROW example:**
```sql
THROW 50001, 'An Error Occurred', 0;
```

## **4. @@ERROR System Variable**
- **Returns last error number** (0 = no error)
- **Resets after each statement** - Must capture immediately
- **Legacy method** (use TRY/CATCH instead)

**Example with capture:**
```sql
DECLARE @ErrorValue INT;
RAISERROR('Message', 16, 1);
SET @ErrorValue = @@ERROR;  -- Capture immediately
IF @ErrorValue <> 0
    PRINT 'Error=' + CAST(@ErrorValue AS VARCHAR(8));
```

## **5. TRY/CATCH Structured Exception Handling**
**Structure:**
```sql
BEGIN TRY
    -- Code that might error
END TRY
BEGIN CATCH
    -- Error handling
END CATCH
```

**Key Rules:**
- **CATCH must immediately follow END TRY** (no statements between)
- **TRY/CATCH can be nested**
- **No FINALLY block** in T-SQL (unlike other languages)
- **Error info persists** throughout CATCH block

## **6. Error Functions in CATCH Block**
- **`ERROR_NUMBER()`** - Error number
- **`ERROR_MESSAGE()`** - Error text
- **`ERROR_SEVERITY()`** - Severity level
- **`ERROR_STATE()`** - State code
- **`ERROR_LINE()`** - Line number
- **`ERROR_PROCEDURE()`** - Procedure name (NULL if not in procedure)

**Example:**
```sql
BEGIN CATCH
    PRINT 'Error: ' + ERROR_MESSAGE();
    PRINT 'Line: ' + CAST(ERROR_LINE() AS VARCHAR);
END CATCH
```

## **7. Non-Catchable Errors**
**TRY/CATCH CANNOT catch:**
- **Compile errors** (syntax errors, missing objects in batch)
- **Deferred name resolution errors** (when procedure references missing table)
- **Severity 10 or lower** (informational messages)
- **Most severity 20+** (system-level/fatal errors)

**Note:** Non-catchable errors in called procedures can often be caught in calling code.

## **8. Rethrowing Errors with THROW**
- **In CATCH block:** `THROW;` (no parameters) re-throws original error
- **Preserves original error info** (number, message, severity, state)
- **Useful for logging then passing error to client**

**Example:**
```sql
BEGIN TRY
    -- Code that fails
END TRY
BEGIN CATCH
    -- Log error details
    EXEC LogError;
    THROW;  -- Re-throw to client
END CATCH
```

## **9. Managed Code Errors (SQL CLR)**
- **Unhandled .NET exceptions** return as error **6522** to T-SQL
- **Should handle errors in .NET code** when possible
- **Nested errors** may wrap real cause

## **10. Best Practices**
1. **Use TRY/CATCH** over @@ERROR for new code
2. **Log errors** before re-throwing
3. **Use THROW** for consistency (SQL Server 2012+)
4. **Test error conditions** thoroughly
5. **Consider XACT_ABORT** with THROW for transaction safety
