## **1. Transaction Basics**
- **Transaction = Group of tasks** that must succeed or fail together (all-or-nothing)
- **Two types:**
  1. **Autocommit** - Single DML statements (default behavior)
  2. **Explicit** - User-defined with BEGIN/COMMIT/ROLLBACK
- **Purpose:** Prevent partial completion when multiple operations are logically related

## **2. Problem: Batches Without Transactions**
- **Individual DML statements auto-commit** when successful
- **Runtime errors** can leave database in inconsistent state (some statements succeed, others fail)
- **Example:** First INSERT succeeds, second INSERT fails → partial data persisted

## **3. Transaction Control Language (TCL)**
**Three key commands:**
1. **`BEGIN TRANSACTION`** (or `BEGIN TRAN`) - Starts explicit transaction
2. **`COMMIT TRANSACTION`** - Makes changes permanent, releases locks
3. **`ROLLBACK TRANSACTION`** - Undoes all changes, releases locks

**Transaction flow with error handling:**
```sql
BEGIN TRY
    BEGIN TRANSACTION
        -- Multiple DML statements
    COMMIT TRANSACTION  -- Only if all succeed
END TRY
BEGIN CATCH
    -- Error handling
    ROLLBACK TRANSACTION  -- Undo if any fail
END CATCH
```

## **4. XACT_STATE() Function**
**Determines transaction state in CATCH block:**
- **`0`** - No active user transaction
- **`1`** - Active, committable transaction
- **`-1`** - Active, uncommittable transaction (must rollback)

**Usage:**
```sql
BEGIN CATCH
    IF XACT_STATE() = -1
        ROLLBACK TRANSACTION;
    -- Error handling
END CATCH
```

## **5. SET XACT_ABORT**
- **Controls automatic rollback** on runtime errors
- **`SET XACT_ABORT ON`** - Automatically rolls back transaction on error (except in TRY block)
- **`SET XACT_ABORT OFF`** - Default, doesn't auto-rollback
- **With TRY/CATCH:** Errors in TRY block leave transaction open but uncommittable

## **6. Transaction Characteristics**
- **Transactions are connection-specific** (cannot span connections)
- **Last until:** COMMIT, ROLLBACK, or connection termination (auto-ROLLBACK)
- **Nested transactions:** Inner COMMIT doesn't save if outer ROLLBACK occurs
- **Resource holding:** Transactions hold locks - keep them short!

## **7. Key Patterns**

**Basic transaction pattern:**
```sql
BEGIN TRANSACTION
    -- DML statements
IF @@ERROR = 0
    COMMIT TRANSACTION
ELSE
    ROLLBACK TRANSACTION
```

**TRY/CATCH with transaction pattern (recommended):**
```sql
BEGIN TRY
    BEGIN TRANSACTION
        INSERT INTO Table1...
        INSERT INTO Table2...
    COMMIT TRANSACTION
END TRY
BEGIN CATCH
    IF @@TRANCOUNT > 0
        ROLLBACK TRANSACTION
    -- Handle error
END CATCH
```

## **8. Critical Rules & Best Practices**
1. **Always pair BEGIN TRAN with COMMIT or ROLLBACK**
2. **Check transaction state** before ROLLBACK in CATCH
3. **Use `@@TRANCOUNT`** to check open transactions
4. **Keep transactions short** to minimize locking
5. **Test with SELECT first** before UPDATE/DELETE in transaction
6. **Consider isolation levels** for concurrency (beyond this module)

## **9. Common Issues & Solutions**
**Problem:** Transaction left open (orphaned)
**Solution:** Check `@@TRANCOUNT`, ensure ROLLBACK in error handling

**Problem:** Partial success in batch
**Solution:** Wrap related DML in explicit transaction

**Problem:** Deadlocks
**Solution:** Keep transactions short, access objects in consistent order

### **Most Likely Quiz Questions:**
1. **"What happens if you don't COMMIT or ROLLBACK a transaction?"** (Transaction remains open, locks held, auto-ROLLBACK on disconnect)
2. **"What's the difference between autocommit and explicit transactions?"** (Autocommit = single statement, explicit = user-controlled group)
3. **"When should you use XACT_STATE()?"** (In CATCH block to determine if transaction can be committed)
4. **"What does SET XACT_ABORT ON do?"** (Auto-rollback on runtime errors)
5. **"True/False: A COMMIT in a nested transaction saves changes if outer transaction rolls back."** (False)
6. **"How do you prevent partial success in a batch of DML statements?"** (Wrap in BEGIN TRAN...COMMIT/ROLLBACK)
7. **"What error handling pattern is recommended for transactions?"** (TRY/CATCH with ROLLBACK in CATCH)
